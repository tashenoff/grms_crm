# Архитектура проекта CRM Bot System

## Обзор

CRM Bot System был реорганизован с монолитной архитектуры в модульную для улучшения поддерживаемости, тестируемости и масштабируемости. Этот документ описывает новую архитектуру проекта и объясняет основные принципы организации кода.

## Основная структура

```
api/
├── __init__.py         # Инициализация приложения
├── models/             # Модели данных
│   ├── __init__.py
│   └── lead.py         # Модель заявки
├── routes/             # Маршруты API
│   ├── __init__.py
│   └── lead_routes.py  # Маршруты для заявок
├── services/           # Сервисный слой (бизнес-логика)
│   ├── __init__.py
│   └── lead_service.py # Логика работы с заявками
└── utils/              # Вспомогательные функции
    ├── __init__.py
    ├── database.py     # Функции для работы с БД
    └── helpers.py      # Общие утилиты
```

## Слои архитектуры

### 1. Модели (Models)

Модели представляют сущности бизнес-домена и инкапсулируют данные и их поведение.

**Пример**: `Lead` в `api/models/lead.py`

- Представляет заявку в системе
- Содержит методы для преобразования объекта в словарь 
- Инкапсулирует форматирование и обработку данных 

```python
class Lead:
    def __init__(self, db_row):
        self.id = db_row['id']
        # ... остальные поля ...
        
    def to_dict(self):
        return {
            'id': self.id,
            # ... остальные поля ...
        }
```

### 2. Сервисы (Services)

Сервисы содержат бизнес-логику приложения и выступают промежуточным слоем между моделями и маршрутами.

**Пример**: `LeadService` в `api/services/lead_service.py`

- Предоставляет методы для работы с заявками 
- Инкапсулирует сложную логику работы с БД
- Управляет созданием и обработкой моделей

```python
class LeadService:
    @staticmethod
    def get_all_leads():
        conn = get_db()
        cursor = conn.cursor()
        # ... логика получения данных ...
        leads = [Lead(row) for row in lead_rows]
        # ... дополнительная обработка ...
        return [lead.to_dict() for lead in leads]
```

### 3. Маршруты (Routes)

Маршруты определяют API приложения и обрабатывают HTTP-запросы, используя сервисы для получения или изменения данных.

**Пример**: Маршруты в `api/routes/lead_routes.py`

- Определяют URL-шаблоны и HTTP-методы
- Вызывают соответствующие сервисы для обработки запросов
- Преобразуют результаты в HTTP-ответы

```python
@leads_bp.route('/leads')
def get_leads():
    leads = LeadService.get_all_leads()
    return jsonify(leads)
```

### 4. Утилиты (Utils)

Утилиты предоставляют общие функции, используемые во всем приложении.

**Пример**: Функции работы с БД в `api/utils/database.py`

```python
def get_db():
    conn = sqlite3.connect(db_path)
    conn.row_factory = sqlite3.Row
    return conn
```

**Пример**: Вспомогательные функции в `api/utils/helpers.py`

```python
def format_date(date_str):
    date_obj = datetime.strptime(date_str, '%Y-%m-%d %H:%M:%S')
    return date_obj.strftime('%Y-%m-%d %H:%M:%S')
```

## Точка входа приложения

Файл `app.py` является точкой входа в приложение и использует фабричную функцию `create_app()` из модуля `api` для создания и настройки экземпляра Flask.

```python
from api import create_app

app = create_app()

if __name__ == "__main__":
    app.run(host="0.0.0.0", port=5000)
```

## Поток данных

1. Запрос приходит на соответствующий маршрут
2. Маршрут вызывает метод сервиса
3. Сервис взаимодействует с базой данных через утилиты
4. Сервис создает экземпляры моделей и выполняет бизнес-логику
5. Результат возвращается обратно в маршрут
6. Маршрут формирует HTTP-ответ

## Преимущества новой архитектуры

1. **Разделение ответственности**: каждый модуль отвечает за свою часть функциональности
2. **Улучшенная читаемость**: меньшие файлы легче понимать и поддерживать
3. **Тестируемость**: модули можно тестировать независимо друг от друга
4. **Масштабируемость**: легко добавлять новые функции, не нарушая существующие
5. **Повторное использование кода**: общие утилиты можно использовать в разных частях проекта

## Рекомендации по расширению

При добавлении новой функциональности:

1. Создайте модели для новых сущностей в `api/models/`
2. Реализуйте бизнес-логику в сервисах в `api/services/`
3. Добавьте новые маршруты в `api/routes/`
4. При необходимости расширьте утилиты в `api/utils/`
