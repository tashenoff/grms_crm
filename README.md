# CRM Bot System

## Описание
Система управления заявками с:
- Telegram-ботом для обработки заказов
- Веб-интерфейсом для менеджеров
- Отслеживанием статусов (Новая, В работе, Доставка, Завершена)

## Требования
- Python 3.9+
- Node.js 14+
- SQLite (встроенная)
- Telegram Bot API токен (получите у @BotFather)

## Установка

### Подготовка окружения
1. Клонировать репозиторий:
   ```bash
   git clone https://github.com/yourusername/crm-bot-system.git
   cd crm-bot-system
   ```

2. Установить Python-зависимости:
   ```bash
   pip install -r requirements.txt
   ```

3. Установить Node.js зависимости для фронтенда:
   ```bash
   cd frontend
   npm install
   cd ..
   ```

### Настройка переменных окружения
1. Создайте файл `.env` в корневой директории проекта со следующим содержимым:
   ```
   TELEGRAM_BOT_TOKEN=ВАШТОКЕНБОТА
   TELEGRAM_CHAT_ID=ВАШИДЧАТА
   ```

2. Где:
   - `ВАШТОКЕНБОТА` - токен Telegram-бота, полученный от @BotFather (например, `7793871539:AAEZ5Jw6_X96YnOUZMPptfogx4ej-SrQJns`)
   - `ВАШИДЧАТА` - ID чата, куда бот будет отправлять уведомления (например, `-1002506448215` для группового чата)

3. Настройка фронтенда - создайте файл `.env.local` в директории `frontend` со следующим содержимым:
   ```
   NEXT_PUBLIC_API_URL=http://localhost:5000
   ```

## Запуск

### 1. Запуск API сервера (Flask)
```bash
python app.py
```
Сервер будет запущен на `http://localhost:5000`

### 2. Запуск Telegram-бота
```bash
python crm_bot.py
```
Бот начнет отслеживать сообщения в Telegram и синхронизировать статусы заявок.

### 3. Запуск веб-интерфейса (Next.js)
```bash
cd frontend
npm run dev
```
Веб-интерфейс будет доступен по адресу `http://localhost:3000`

## База данных

### Структура БД
БД SQLite (`crm.db`) создается автоматически при первом запуске и содержит следующие таблицы:

1. **leads** - Заявки клиентов:
   - id - уникальный идентификатор
   - telegram_id - ID пользователя Telegram
   - username - имя пользователя
   - message - исходное сообщение
   - status - статус заявки ('new', 'in_progress', 'delivery', 'accepted', 'declined')
   - client_name, phone, city, address - информация о клиенте
   - order_details, total_amount, order_date - информация о заказе
   - source - источник заявки ('telegram', 'web', 'call', и т.д.)
   - created_at - дата создания

2. **users** - Пользователи Telegram:
   - telegram_id - ID пользователя
   - username - имя пользователя
   - first_name - имя
   - created_at - дата регистрации

3. **lead_messages** - Связь между заявками и сообщениями Telegram:
   - id - уникальный идентификатор
   - lead_id - ID заявки
   - message_id - ID сообщения в Telegram
   - is_deleted - флаг удаления
   - created_at - дата создания

### Резервное копирование БД
Регулярно делайте резервные копии базы данных:
```bash
cp crm.db crm.db.backup-$(date +%Y%m%d)
```

## Архитектура проекта
Проект реорганизован с использованием модульной архитектуры для лучшей поддерживаемости и масштабируемости:

### Структура API
```
api/
├── __init__.py         # Инициализация приложения
├── models/             # Модели данных
│   ├── __init__.py
│   └── lead.py         # Модель заявки
├── routes/             # Маршруты API
│   ├── __init__.py
│   └── lead_routes.py  # Маршруты для заявок
├── services/           # Сервисный слой (бизнес-логика)
│   ├── __init__.py
│   └── lead_service.py # Логика работы с заявками
└── utils/              # Вспомогательные функции
    ├── __init__.py
    ├── database.py     # Функции для работы с БД
    └── helpers.py      # Общие утилиты
```

### Принципы модульной архитектуры
- **Разделение ответственности**: каждый модуль отвечает за свой функционал
- **Чистота кода**: отделение бизнес-логики от маршрутов и моделей
- **Тестируемость**: модули могут быть протестированы независимо друг от друга
- **Масштабируемость**: легко добавлять новую функциональность без изменения существующего кода

### Маршруты API
- **/** - Главная страница
- **/leads** - Список всех заявок
- **/lead_details/{id}** - Детальная информация о заявке
- **/user_leads/{phone}** - Заявки пользователя по номеру телефона
- **/stats** - Статистика по заявкам
- **/reset** - Сброс базы данных (POST-запрос)
- **/create_lead** - Создать новую заявку (POST-запрос)
- **/update_lead/{id}** - Обновить заявку (POST-запрос)
- **/delete_lead/{id}** - Удалить заявку (POST-запрос)

## Синхронизация статусов
Система поддерживает двунаправленную синхронизацию статусов между веб-интерфейсом и Telegram:

1. При изменении статуса через веб-интерфейс:
   - Изменение сохраняется в БД
   - Бот обновляет сообщение в Telegram

2. При изменении статуса через кнопки в Telegram:
   - Бот обновляет статус в БД
   - Веб-интерфейс отображает актуальный статус при обновлении

Для корректной работы синхронизации необходимо:
- Запустить и бота, и API сервер
- При создании заявки через веб-интерфейс, она автоматически публикуется в Telegram
- Заявки, созданные через Telegram, автоматически появляются в веб-интерфейсе

## Устранение неполадок

### Бот не отправляет сообщения в Telegram
1. Убедитесь, что бот добавлен в чат/группу
2. Проверьте правильность токена бота и ID чата в файле .env
3. Перезапустите бота: `python crm_bot.py`

### Не обновляются статусы в Telegram
1. Убедитесь, что таблица `lead_messages` содержит записи, связывающие ID заявок с ID сообщений
2. Убедитесь, что бот запущен и работает без ошибок
3. Проверьте логи бота на наличие ошибок

### Не загружается веб-интерфейс
1. Убедитесь, что сервер API работает: http://localhost:5000/leads
2. Проверьте настройки в frontend/src/config.js
3. Перезапустите сервер разработки: `cd frontend && npm run dev`
