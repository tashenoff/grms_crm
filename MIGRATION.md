# Инструкция по переходу на новую архитектуру CRM Bot System

Эта инструкция описывает, как выполнить переход с монолитной архитектуры на новую модульную.

## Подготовка к переходу

1. Убедитесь, что у вас есть резервная копия базы данных
```bash
cp crm.db crm.db.backup
```

2. Создайте ветку в системе контроля версий (если используется)
```bash
git checkout -b architecture-refactoring
```

## Шаг 1: Проверка зависимостей

Убедитесь, что у вас установлены все необходимые пакеты:
```bash
pip install -r requirements.txt
```

## Шаг 2: Запустите тестирование новой архитектуры

Проверьте, что новое приложение работает корректно:
```bash
python app_new.py
```

Откройте в браузере http://localhost:5000 и убедитесь, что все функции работают как ожидается.

## Шаг 3: Замена основного файла приложения

1. Создайте резервную копию старого файла `app.py`:
```bash
cp app.py app.py.old
```

2. Замените основной файл приложения новым:
```bash
mv app_new.py app.py
```

## Шаг 4: Проверка работоспособности

Запустите приложение и проверьте его работоспособность:
```bash
python app.py
```

Убедитесь, что:
- Все маршруты API работают корректно
- Заявки отображаются и обрабатываются
- Статистика корректно вычисляется
- Все интеграции с ботами и фронтендом продолжают работать

## Типичные проблемы и их решение

### Проблема с импортами

Если возникают ошибки импорта, убедитесь, что каталог проекта находится в переменной PYTHONPATH:

```bash
export PYTHONPATH=$PYTHONPATH:$(pwd)
```

### Проблемы с доступом к базе данных

Если приложение не может подключиться к базе данных, проверьте пути в `api/utils/database.py` и убедитесь, что они корректны для вашей системы.

### Проблемы с шаблонами

Если шаблоны не находятся, проверьте настройки в `api/__init__.py`:

```python
app = Flask(__name__, template_folder='../templates')
```

## Дополнительные рекомендации

### Для разработчиков

- Ознакомьтесь с файлом `ARCHITECTURE.md` для понимания новой архитектуры
- Добавляйте новую функциональность в соответствующие модули
- Используйте юнит-тесты для проверки отдельных компонентов

### Для администраторов

- Обновите документацию запуска и мониторинга приложения
- При обновлении системы используйте скрипты миграции для сохранения данных

## Откат в случае проблем

Если новая архитектура вызывает проблемы, вы можете вернуться к старой версии:

```bash
mv app.py.old app.py
```

## Подтверждение успешного перехода

После успешного перехода на новую архитектуру:

1. Удалите резервные копии и временные файлы
```bash
rm app.py.old
```

2. Зафиксируйте изменения в системе контроля версий
```bash
git add .
git commit -m "Refactor: Migrate to modular architecture"
```
